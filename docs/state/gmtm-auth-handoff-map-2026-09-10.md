# GMTM authentication handoff map

September 10, 2026. Read-only source investigation for the [approved athlete journey](gmtm-sparq-athlete-journey-2026-09-10.md). This is an implementation recommendation, not an implemented bridge, provider capability verification or deployed-state claim.

## Recommendation

Add a narrow GMTM-issued, one-use authorization-code exchange. GMTM validates its existing session and represented athlete; SPARQ consumes the resulting server-verified identity, starts its own session without another routine sign-in, and retains explicit return context. Keep raw GMTM session IDs out of URLs and SPARQ frontend storage. Keep the existing Agent ownership checks and private work intact.

For the first self-owned athlete slice, preserving Clerk behind an automatic server-verified bootstrap is the smallest likely change to SPARQ's current UI/auth dependencies. Confirm the supported Clerk mechanism and instance settings before committing to that implementation. A mapping row or shared hostname does not establish a Clerk session. If the bootstrap cannot meet revocation/account-switch requirements, use a dedicated GMTM-backed SPARQ session adapter; that is a larger, separately reviewed auth change.

Junior delegation is a real missing capability. The active child session alone does not prove which parent is operating it. Do not silently treat that session as an independently authenticated child or log a parent into a child's self-owned Clerk account.

## Operator, athlete and family identity

`POST /v2/users/switch` validates `users.parent_id === req.session.user_id`, then creates a new 90-day child session. That record's `user_id` is the child; it contains neither the parent/operator ID nor original parent-session reference. [resources/user/user.resolver.js:2926](https://github.com/gmtmsports/gmtm-api-v2/blob/93c18b14c848fa123017356aa2db309b28350c65/resources/user/user.resolver.js#L2926)

Mobile stores the original parent data under `@parentData`, replaces the active token/data with the child session, and restores the parent locally when switching back. The impersonation flag is local UI state. [screens/ManageChildren.js:105](https://github.com/gmtmsports/gmtm-expo/blob/3c7949daa66dcb4b49218b11d3618efcf8d5ad65/screens/ManageChildren.js#L105), [contexts/AuthContext.js:378](https://github.com/gmtmsports/gmtm-expo/blob/3c7949daa66dcb4b49218b11d3618efcf8d5ad65/contexts/AuthContext.js#L378)

The alternate `generateChildSession` checks `user_parents`, not `users.parent_id`, and likewise mints a child-only session. Do not combine these relationship models implicitly. [resources/user/user.resolver.js:945](https://github.com/gmtmsports/gmtm-api-v2/blob/93c18b14c848fa123017356aa2db309b28350c65/resources/user/user.resolver.js#L945) PR 73's corrected detach changes the database relationship/contact/claim state but does not revoke existing child sessions. [resources/user/user.resolver.js:3133](https://github.com/gmtmsports/gmtm-api-v2/blob/93c18b14c848fa123017356aa2db309b28350c65/resources/user/user.resolver.js#L3133)

The existing SPARQ claim/link and workspace contracts are one self-owned athlete per Clerk identity: [claim conflict guard](../../backend/claims_api.py#L286), [strict forward/reverse workspace owner check](../../backend/athlete_workspace.py#L152). Guardian access needs an explicit actor/athlete authorization context and separately scoped saved work; changing that single mapping to follow the selected child would corrupt identity isolation.

For an interim delegated exchange, the native client could present its active child session **and** the retained parent session to GMTM over the authenticated POST. GMTM must independently validate both, verify the current `users.parent_id` relation, and bind both identities to the grant. Treat these as credentials, not trusted local flags. Expired/missing parent evidence cannot be recovered by guessing from a child ID or email. Longer-term, record operator/session provenance server-side when switching. Existing unmarked sessions require a deliberate migration/re-authentication policy.

## Logout and returning context

Web `/sign-out` currently clears cookies and redirects; it does not invoke Redis deletion. [middleware.js:295](https://github.com/gmtmsports/gmtm.com/blob/b0293a2cc918da59afb53cc75c0cfdd71769c4a3/middleware.js#L295) Mobile sign-out clears local storage, logs out purchases and removes the push device, but does not invoke API session deletion. [contexts/AuthContext.js:353](https://github.com/gmtmsports/gmtm-expo/blob/3c7949daa66dcb4b49218b11d3618efcf8d5ad65/contexts/AuthContext.js#L353) The API does expose a separate single-session `/v2/sign-out` deletion handler. [resources/session/session.resolver.js:326](https://github.com/gmtmsports/gmtm-api-v2/blob/93c18b14c848fa123017356aa2db309b28350c65/resources/session/session.resolver.js#L326)

Consequently, creating an independent Clerk session once and forgetting GMTM would survive GMTM UI logout and family detach. Required integration work: revoke the relevant source/grant on logout, and require an active bounded GMTM authorization context on SPARQ personal requests. Refresh/revalidate without second sign-in while the GMTM session remains valid; fail closed on expiry, logout or lost guardian relation. Define switching semantics for existing tabs rather than silently repainting a different athlete. Reuse current owner/revision and draft-conflict guards.

The GMTM combine page uses `components/organisms/Page`, which renders `components-v2/organisms/Header`; that is the source-traced signed-in header for this journey, rather than assuming the unrelated newer `components/header.jsx` is live everywhere. [pages/virtuals/[virtual_id]/[slug]/index.js:28](https://github.com/gmtmsports/gmtm.com/blob/b0293a2cc918da59afb53cc75c0cfdd71769c4a3/pages/virtuals/[virtual_id]/[slug]/index.js#L28), [components/organisms/Page/index.js:23](https://github.com/gmtmsports/gmtm.com/blob/b0293a2cc918da59afb53cc75c0cfdd71769c4a3/components/organisms/Page/index.js#L23)

[navigators/RootNav.js:549](https://github.com/gmtmsports/gmtm-expo/blob/3c7949daa66dcb4b49218b11d3618efcf8d5ad65/navigators/RootNav.js#L549) The iOS source declares `applinks:gmtm.com`; Android intent filters and live association files were not verified. ## Minimal implementation touchpoints

1. **GMTM API:** a small dedicated `resources/agent-handoff` route/resolver registered with the existing resource router. Implement start, consume and narrow active-context validation. Read the exact current session from `sessions`; reject missing, malformed, unverified or unauthorized identities. Generate a random, short-lived, single-use opaque code, store only its hash plus necessary identity/context in a separate Redis namespace, and atomically consume it. Bind SPARQ audience, exact approved callback, browser challenge/state, initiating session and operator/athlete pair. Recheck authorization at consumption. The code expires within about 60 seconds and never returns the source bearer. Reject replays, conflicting account destinations and caller-controlled redirects.
2. **GMTM web:** add an `Open SPARQ` CTA to the traced Header v2 and a post-submission placement, both using one first-party authorization entry. Preserve event/task/profile return context as validated structured IDs. Read source cookies server-side; start/redeem must be bound to the initiating browser, with CSRF protection. Keep the legacy uploader untouched. Update the actual sign-out middleware path to revoke source/bridge authority, including appropriate domain/host cookie clearing.
3. **SPARQ:** add an auth-start/callback adapter and server-to-server exchange client. Use a verified GMTM ID to resolve the existing exact link; never auto-link by name/email or overwrite an existing mapping. First-entry account creation/mapping must be idempotent and transactional with explicit conflict handling. The chosen Clerk bootstrap must be verified in the actual dedicated instance; do not turn a family grant into impersonation of another person's Clerk user. Extend candidate route/config/package guards for only these reviewed auth paths. Add a persistent return action to `ProfileWorkspaceShell.tsx`, scoped to the verified handoff context. Keep author edits and saved-work ownership checks.
4. **GMTM mobile:** one shared launcher used from the relevant home/combine screens, authenticated using the current token. Carry actor/athlete evidence for the reviewed family path; exchange only an ephemeral code into the browser. Use the existing native return routes, preserving event/task context and revalidating the current account on resume. Coordinate sign-out/switch invalidation with `AuthContext.js`.

The existing API hook logs request URLs and its error handler includes session/headers/body metadata ([server/index.js:66](https://github.com/gmtmsports/gmtm-api-v2/blob/93c18b14c848fa123017356aa2db309b28350c65/server/index.js#L66), [server/index.js:130](https://github.com/gmtmsports/gmtm-api-v2/blob/93c18b14c848fa123017356aa2db309b28350c65/server/index.js#L130)). Exclude the new exchange's credentials/codes from both application and ingress logs; keep callback pages free of analytics/third-party assets until the code is consumed and removed. This is a concrete requirement of adding an authentication exchange, not a broad unrelated logging cleanup.

Do not use the mutation-heavy `/sessions/ids` route as a supposedly read-only test.

Junior acceptance additionally requires authenticated operator/athlete evidence, live relationship checks at consume and access, parent/sibling isolation, detach revocation, parent-session expiry and switch-back behavior. Until implemented, the entry must identify an unsupported delegated context honestly and preserve the existing GMTM flow. A synthetic child Clerk session is not proof of the real guardian journey.
