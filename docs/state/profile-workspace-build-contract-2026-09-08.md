# First working profile workspace

Owner: Codex, existing `codex/athlete-home-first-value` lane. Starting commit `e7750e6`. Joey asked to continue and identify the highest priorities; this begins implementation of the accepted profile-value direction.

## Outcome and boundaries

An authenticated athlete can inspect their own canonical identity and bounded shareable recorded measurements, understand supported observations, select evidence, state a goal/intended use and create/edit/copy a factual summary or introduction. The interface has no duplicate combine checklist or persistent chat panel. An empty or failed source read never produces invented performance data.

This is the evidence and action-preparation foundation. It does not yet discover opportunities, evaluate film, calibrate athletic potential, prove selection outcomes or establish willingness to pay. Its deterministic summary is labeled as such, not passed off as model analysis. No paid offer, public profile publication, external outreach, provider call or production deployment is part of this build.

Add an explicitly selected `profile` frontend surface and `profile_candidate_app:app` backend entry. Preserve the default legacy and focused combine behavior. Reuse strict identity linkage and configuration/startup isolation; do not broadly remount legacy profile/sharing/recruiting routes. GMTM remains read-only, no new schema, and the first adapter conservatively excludes private/unconfirmed publication scopes. No user-supplied athlete ID selects source data.

## Assignments

- Backend subagent: new `athlete_evidence.py` and focused tests, canonical schema/visibility mapping, bounded reads, truthful states and source attribution.
- Frontend subagent: new profile workspace/shell, strict response parser/draft helpers and actual-component interaction checks.
- Root: explicit surface/route integration, authenticated ASGI/policy verification, complete local app checks, source review and handoff.
- Read-only context review: identify existing authorized owner-profile evidence and current live-test boundaries. Other athlete records are not an implied test dataset.

## Acceptance

1. Exact owner/reverse-owner checks precede GMTM reads; ambiguous links fail. Queries are parameterized, bounded and SELECT-only, and connections close on errors. No private contacts/scout notes, unverified benchmark or selection claim leaves the adapter.
2. Missing measurements, malformed data and failed reads are distinguished. Every observation cites only displayed evidence IDs; units/dates/provenance remain attributable and uncertainty explicit.
3. Draft creation uses selected facts and the user's real goal/use. Athlete can edit and copy the exact output; failed copy has a manual fallback and never claims success. No send/share action or hidden profile URL.
4. Account change/logout clears snapshots and drafts; stale requests cannot restore another account. Text renders safely without raw HTML. Loading, link/auth/conflict/source-error and zero-measurement states are usable.
5. Profile app exposes only its manifest; it cannot call combine help, legacy research, sending or broad public-report routes. Existing combine policy/default behavior remains verified.
6. Run focused offline backend/ASGI and actual-component checks, current-source TypeScript and a bounded full-app local verification as available. Synthetic behavior proves mechanics only.
